# 동네 SOS

Приложение о физических барьерах в районе (배리어프리 및 생활편의).
Ядро продукта: **одна проблема → коллективное подтверждение → числовой приоритет → закрытие цикла с фото результата.**

Похожая проблема в 50 метрах — это не новая заявка, а `확인 +1` к существующей.
Если правка не работает на эту фразу — её не нужно делать.

## Стек

- Мобильное: React Native + Expo (TypeScript)
- API: Node + Express (TypeScript), только 9 endpoint'ов
- Данные: Supabase — PostgreSQL + PostGIS, Storage, Realtime
- Админка: React (web), отдельный проект в `/admin-web`
- Карта: Kakao Maps SDK (только на клиенте)

## Контракт — читать до написания кода

- `contract/types.ts` — единственный источник правды по формам данных
- `contract/fixtures.json` — реальные примеры ответов всех endpoint'ов
- `contract/README.md` — 9 endpoint'ов одним списком

## Правила, которые нарушать нельзя

1. **snake_case везде.** Имена полей в JSON = имена колонок в базе. Никакого camelCase и никакого слоя преобразования.
2. **Один экран — один запрос к API, внутри — один запрос к базе.** Если в логах десятки одинаковых SQL подряд — это N+1, переделать.
3. **Правим только свою директорию** (карта владения ниже). Нужна правка у соседа — просим соседа.
4. **Приоритет считается только на сервере**, в одной функции `calcPriority()`. Клиент получает готовое число и готовую разбивку.
5. **`확인 +1` — одна транзакция:** вставка в `confirmations` + инкремент `confirmation_count` + пересчёт `priority_score`. Либо всё, либо ничего.
6. **Любая внешняя фича умеет отключаться.** AI-классификация и распознавание речи — с таймаутом 3 с и тихим отказом: пользователь просто заполняет форму сам.
7. **Фото сжимаются на устройстве** до 1280 px / q70 перед загрузкой. На карте и в списках — только превью (`before_thumb_url`). Полный снимок — лишь на экране деталей.
8. **Realtime-подписка живёт только пока экран видим.** Ушёл в фон — отписались. На каждом экране обязательно есть и обычная загрузка, и «потянуть вниз».
9. **Device-идентификация:** каждый запрос несёт заголовок `X-Device-Id`. Регистрации у жителя нет. Логин есть только у оператора админки.
10. **Никогда не логировать точные координаты и `X-Device-Id` вместе** — это деанонимизация.

## Формула приоритета (0–100)

```
confirmations : min(30, count * 2.5)
severity      : low 12 | medium 22 | high 35
duration      : min(15, days_open * 0.75)
impact        : min(20, groups * 5)
```

Контрольный пример: 13 подтверждений, `high`, 4 дня, 2 группы → 30 + 35 + 3 + 10 = **78**.
Если ваш код даёт не 78 — он неправильный.

## Задача считается готовой, если

- запускается не только у автора, но и у соседа;
- работает на данных из `contract/fixtures.json`, а не на выдуманных;
- её видно в сквозном сценарии демонстрации;
- ветка влита в `main` в тот же день.

## Чего не делать

- Не добавлять чат, рейтинги, ленту, социальные функции.
- Не добавлять категории «чтобы было» — их ровно четыре.
- Не делать сложную авторизацию. У жителя её нет вовсе.
- Не переименовывать поля контракта в одиночку.
- Не оптимизировать то, что не измерено.
